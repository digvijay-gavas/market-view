# ARC-0001: Daily positions and shared quote observations

Status: Implemented; real-account enrollment and offline consent are deployment steps.
Date: 2026-11-23.

## Context and decision

Full snapshots remain supported. The local collector separates account quantity
and cost reconciliation from shared market prices. This avoids opening each
account's browser every ten minutes and provides independent provenance for the
two kinds of data. A complete daily baseline avoids replay dependencies in a
delta-only chain. Net changes do not establish trade history.

## Run flow

1. Read config/checkpoints and gate on enabled, verified calendar, market window
   and randomized next-run time. Acquire the local lock and refresh Google access.
2. Read each account's latest shared positions, falling back to legacy holdings.
   Reconcile accounts missing a baseline for the current IST market day. Keep
   valid prior data when authentication or parsing fails. Persist PIN guards
   before automatic entry and checkpoint account outcomes before cache work.
3. Deduplicate instruments across accounts. Fetch one shared quote universe;
   preserve timestamps for failed instruments. Publish an immutable observation
   only when at least one instrument received a new valid quote.
4. Compare the source manifest with the shared dashboard cache. For new inputs,
   load the store, materialize holdings, calculate the all-accounts view and save
   the cache only if a second manifest read agrees. Publish run status.
5. The static viewer reads the same shared cache and source formats. The worker
   does not run inside the viewer or in GitHub Actions.

## Boundaries and compatibility

- Browser authorization, OTP and account-alias confirmation are manual setup.
  Only enrolled profiles run headlessly. PIN errors/challenges stop automatic
  attempts until manual inspection. Non-GET order/withdraw paths are blocked.
- The worker writes new sources, catalog additions, status and shared cache;
  the browser's write scope still only updates the named shared cache. Neither
  component changes sharing permissions. Family access follows folder ACLs.
- Daily legacy captures keep existing readers usable. BM/P&L/dividend collection
  remains outside this worker. Shared quotes can value an existing legacy basis.
- Missing historical trades and prices cannot be reconstructed from holdings.
  Recovery fetches the latest state and preserves the observed interval.
- There is no distributed leader lock. Operate one scheduled writer. Exact
  immutable names make retries reusable, but concurrent machines can duplicate
  work or produce a transient mixed view; the next complete run reconciles it.
- Private vault/profile/source-body cache files stay outside the repository.
  Portable encrypted session exports do not guarantee session portability.
- The scheduler requires an awake, signed-in Windows session. Only 2026 holidays
  are bundled. Public quote endpoints may change or refuse automated access.

## Local admin boundary

`automation/admin.mjs` serves the account setup UI only on IPv4 loopback. Its
random launch key establishes an HttpOnly SameSite session. Host validation,
same-origin POST checks, an explicit API header, bounded JSON and an allowlist
of actions protect the local control surface. The launcher reuses an existing
server and opens a new private session; it is excluded from Pages.

`AdminService` shares the worker lock for PIN, configuration and enrollment
changes. Groww enrollment holds a headed context until the user explicitly
confirms the account nickname, or cancels/times out. API status exposes readiness
flags and timestamps, never PINs, tokens, client secrets or browser state.

Saved isolated profiles from the original sibling collector can be selected by
an opaque discovered ID. The server validates their real paths and refuses the
normal Chrome user-data tree. It does not copy or decrypt main-profile cookies.
Selection becomes the account's profile only after confirmation; the worker then
uses it headlessly. Portable imports discard machine-specific paths. A profile
held by another browser fails without killing that browser or removing locks.

Admin tests cover origin/session gates, response redaction, enrollment
confirmation/cancellation, credential locking, scheduling failures and the mobile
UI. Profile tests check metadata-only discovery and rejection of normal Chrome
directories. Actual Groww session validity still requires user enrollment.
