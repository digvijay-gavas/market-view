1. Create a browser OAuth client

In Google Cloud Console, select your project and enable Google Drive API. Configure the Google Auth Platform consent screen. For a personal app in Testing mode, add the intended Google accounts as test users.

Create an OAuth client of type Web application. Under Authorized JavaScript origins, add the exact origin where you open this site: for local use, http://127.0.0.1:5173; for GitHub Pages, https://YOUR-OWNER.github.io. Origins have no path, repository name or trailing slash. Add http://localhost:5173 separately only if you use it.

This app uses the Google Identity Services popup token model. It does not use a backend redirect endpoint, a desktop client, a client secret or a refresh token. Copy only the public web client ID into the dashboard’s connection form.

2. Choose the correct Drive folder

Connect with the Google account that can view the store. Grant https://www.googleapis.com/auth/drive.readonly. This is read access to all files in Drive accessible to that account, not folder-only permission. The reader requests the selected folder’s holdings, dividend reports, catalog and confirmation logs. It never modifies files.

Paste the existing Market store folder link, or find folders named market-data. Select its root: the folder containing _schema and groww.live_holdings. Viewer access is sufficient. Shared drives and Shared with me folders work when the active account has access.

Each user sees only what Google Drive permits that account to read. People who can read the same shared folder intentionally see the same portfolio. Portfolio-account filters are a display convenience, not an authorization boundary.

3. Understand the numbers

The store contains saved captures, not live market prices. Market value is captured quantity × captured price, or the source’s captured current value. Invested is the source’s invested amount, falling back to quantity × average price when available. Unrealised P&L is value minus invested; return is P&L ÷ invested. A missing input is unavailable, never silently zero.

The reader groups holdings by their exact Groww slug. Latest valid holdings captures win per account, including explicit empty accounts. Invalid newest files fall back to older valid snapshots with a warning. P&L-only accounts are identified and excluded; no guessed lot reconstruction, symbol matching or tax calculation. Open holdings XIRR requires a P&L report with dated open lots that exactly reconcile to the current holdings; it excludes closed trades and dividends. Missing or mismatched inputs show Unavailable.

Dividend reports are cumulative and overlapping. Credits are deduplicated by account, ISIN, ex-date, shares and amount. They are shown separately across available report dates, not added to unrealised return. No cash-flow-adjusted returns or daily change are implied.

Confirmation logs can show that unchanged data was rechecked; this does not make its saved price newer. Check both capture and as-of dates. You need another writer or the original Market app to update Drive files; this reader cannot do that.

Security and troubleshooting

An unexpired Google access token and selected folder ID are kept in this tab’s sessionStorage so refresh can restore the dashboard. Portfolio data is cached in IndexedDB for the current sign-in session. Refresh shows it while checking Drive metadata and downloads only changed files. Disconnect or account selection clears the stored session, local portfolio cache and displayed data, and aborts pending requests. Expired, revoked, malformed or mismatched sessions require reconnection. Only the public client ID uses localStorage; no refresh token, analytics or service worker is used. Cache records expire with Google access and are purged when the database next opens.

Disconnect ends this app’s local session; it does not sign you out of Google or revoke its consent. To revoke consent, use your Google account’s Third-party connections settings.

If the popup fails, allow popups and verify the exact authorized origin and Web application client type. If access is denied, check test-user enrollment, granted read-only scope, enabled Drive API and folder permissions. Access tokens expire; connect again when prompted. An unverified or restricted-scope app may require Google verification before broad distribution.

Anyone opening the static site must authorize their own Google account. Hosting the frontend publicly does not publish Drive files, but the source host is trusted code that handles your access token. Do not use an untrusted fork.
